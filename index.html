Software Architecture

Bahasa & Framework

Sistem ini dirancang dengan pendekatan lightweight untuk memastikan performa maksimal pada wall-display yang menyala 24/7, dipadukan dengan manajemen *package* modern di sisi *backend*.

Vanilla JS & DOM

Logika antarmuka murni menggunakan ES6+ JavaScript. Pendekatan ini menghindari beban memori tinggi dari framework reaktif saat melakukan polling AJAX ke server setiap 2 detik.

  • Asynchronous Fetch API
  • Manipulasi DOM Langsung
  • HTML5 Audio (Alarm System)

Tailwind & Chart.js

Antarmuka glassmorphism yang dinamis dibangun sepenuhnya dengan Tailwind CSS. Sementara Chart.js digunakan untuk merender grafik telemetri 24-jam dengan efisiensi tinggi pada elemen Canvas.

  • Utility-First Styling (CDN)
  • Adaptasi Tema (Dark/Light)
  • Data Visualization (Stats)

PHP 8 & Composer

Core backend API dan pelaporan. Menggunakan Composer untuk mengelola ekosistem package pihak ketiga dalam mengkonversi data database MySQL menjadi file ekspor PDF dan XLSX (Excel).

  • PDO MySQL Transactions
  • Composer: PDF Generation
  • Composer: XLSX (Spreadsheet)

Komponen Fisik Fungsi Spesifik & Deskripsi Firmware Protocol
ESP32 Core
Mikrokontroler 32-bit utama untuk memproses akuisisi data sensor, menangani request HTTP, dan *parsing* payload JSON. ArduinoJson, HTTPClient
DHT22
Membaca fluktuasi Suhu (°C) dan Kelembaban Relatif (%) udara dengan tingkat presisi desimal, sangat vital untuk ruang server. DHT.h (Adafruit)
MQ-2 Gas
Pendeteksi kebocoran gas metana dan kepadatan asap (Smoke). Output berupa data Part-Per-Million (PPM) untuk deteksi dini kebakaran. AnalogRead (ADC)
SCT-013
Sensor CT (Current Transformer) Non-invasive AC. Mengukur tarikan arus listrik (Ampere) untuk mengestimasi beban konsumsi Server Rack. EmonLib (Savjee)
EMlock (Magnetic)
Electromagnetic Lock. Menggunakan prinsip magnetik untuk memberikan daya tahan tarik tinggi (Holding Force) dalam mengamankan pintu ruang server utama. Jauh lebih aman dan stabil dibanding selenoid lock standar. Relay / GPIO Write

Cryptography Protocol

AES-256-GCM QR Encryption

Akses fisik ke Ruang Server tidak mengandalkan PIN atau kunci konvensional. Sistem menggunakan QR Code terenkripsi yang dihasilkan secara dinamis, mengadopsi standar enkripsi militer AES (Advanced Encryption Standard) 256-bit dengan mode operasi GCM (Galois/Counter Mode).

1

Dynamic Handshake

Dashboard menghasilkan Token ID dan Timestamp unik yang dienkripsi menjadi QR Code. Token ini memiliki masa kadaluarsa ketat selama 30 detik untuk mencegah Replay Attacks (penggunaan ulang foto QR).

2

GCM Authenticated Encryption

Berbeda dengan mode CBC, Mode GCM menambahkan MAC (Message Authentication Code) / Tag ke dalam payload. Hal ini menjamin bahwa isi QR Code tidak mengalami modifikasi (tampering) sedikitpun di tengah jalan.

3

Hardware EMlock Trigger

Aplikasi Flutter staf TI mendekripsi QR, memvalidasi sesi, dan jika berhasil, server backend (PHP) akan memanipulasi buffer JSON. ESP32 Door Node membaca buffer ini dan memutus arus pada EMlock agar pintu terbuka.

door_system.php (Validation Layer)
// Memecah payload: IV::Ciphertext::Tag list($ivBase64, $cipherBase64, $tagBase64) = explode('::', $payload); $iv = base64_decode($ivBase64); $ciphertext = base64_decode($cipherBase64); $tag = base64_decode($tagBase64); // Dekripsi AES-256-GCM dengan validasi tag otentikasi $decrypted = openssl_decrypt( $ciphertext, 'aes-256-gcm', $SECRET_KEY, OPENSSL_RAW_DATA, $iv, $tag ); if ($decrypted === false) { die(json_encode(['status' => 'DENIED', 'msg' => 'Tampered / Invalid QR'])); }

Storage Layer

Skema Database Relasional

Database db_monitor_server menggunakan engine relasional murni. Setiap tabel dirancang dengan optimasi indexing dan pengaman security hardening terisolasi guna menjamin integritas data operasional RS Sari Mulia.

sensor_logs

Time-Series

Menyimpan snapshot telemetri lingkungan berkala (suhu, kelembaban, kadar asap, dan beban arus listrik). Dilengkapi indeks pada kolom waktu untuk akselerasi grafik Chart.js.

SQL Statement
CREATE TABLE IF NOT EXISTS sensor_logs (
    id INT AUTO_INCREMENT PRIMARY KEY,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    room_temp FLOAT DEFAULT 0,
    room_humi FLOAT DEFAULT 0,
    room_smoke FLOAT DEFAULT 0,
    rack_temp FLOAT DEFAULT 0,
    rack_humi FLOAT DEFAULT 0,
    rack_smoke FLOAT DEFAULT 0,
    current1 FLOAT DEFAULT 0,
    current2 FLOAT DEFAULT 0,
    INDEX (created_at)
);

door_logs

Audit Trail

Jejak audit akses masuk staf IT ke ruang server. Mencatat identitas subjek, status otorisasi (SUCCESS/DENIED), token, serta durasi kunjungan berbasis sensor PIR.

SQL Statement
CREATE TABLE IF NOT EXISTS door_logs (
    id INT AUTO_INCREMENT PRIMARY KEY,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    username VARCHAR(50) NOT NULL,
    token_id VARCHAR(255) NOT NULL,
    device_id VARCHAR(100),
    subject VARCHAR(255),
    status ENUM('SUCCESS', 'DENIED'),
    duration INT DEFAULT 0,
    INDEX (created_at)
);

door_commands

State Queue

Tabel antrean satu baris (Single-row state queue) yang dikontrol oleh server dan dibaca secara berkala oleh ESP32 Door Node untuk memicu aktuator EMlock.

SQL Statement
CREATE TABLE IF NOT EXISTS door_commands (
    id INT PRIMARY KEY DEFAULT 1,
    command INT DEFAULT 1,
    physical_status INT DEFAULT 1
);
INSERT IGNORE INTO door_commands (id, command, physical_status)

Security Cache

Anti-Replay

Terdiri dari door_jti_cache untuk mencegat pemindaian QR berulang (Replay Attack) dan door_brute_force guna melakukan rate-limiting pada perangkat mencurigakan.

SQL Statement
CREATE TABLE IF NOT EXISTS door_jti_cache (
    jti VARCHAR(64) PRIMARY KEY,
    expires_at TIMESTAMP
);

CREATE TABLE IF NOT EXISTS door_brute_force (
    device_id VARCHAR(100) PRIMARY KEY,
    attempts INT DEFAULT 0,
    blocked_until TIMESTAMP NULL
);

system_alerts

Diagnostics

Tempat penyimpanan pusat untuk seluruh laporan anomali sistem, seperti peringatan suhu rak kritis atau node sensor yang terputus dari jaringan secara tiba-tiba.

SQL Statement
CREATE TABLE IF NOT EXISTS system_alerts (
    id INT AUTO_INCREMENT PRIMARY KEY,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    category VARCHAR(50) NOT NULL,
    node_id VARCHAR(50) NOT NULL,
    message VARCHAR(255) NOT NULL,
    status VARCHAR(50) NOT NULL,
    INDEX (created_at)
);

users

Authentication

Mengelola kredensial staf TI dan pengikatan perangkat (Device Binding) melalui kombinasi kunci unik untuk memastikan aplikasi mobile hanya terhubung pada satu unit terpercaya.

SQL Statement
CREATE TABLE IF NOT EXISTS users (
    id INT AUTO_INCREMENT PRIMARY KEY,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    username VARCHAR(50) NOT NULL UNIQUE,
    token_id VARCHAR(255) NOT NULL,
    device_id VARCHAR(100),
    UNIQUE KEY unique_user_device (token_id, device_id)
);

Endpoints & Core Logic

API Documentation

Dokumentasi detail mengenai file PHP (tanpa framework besar) yang menangani routing, otentikasi, I/O *buffer JSON*, hingga pengolahan *export file* melalui pustaka Composer.

iot_logging.php

Telemetry Engine

Berfungsi sebagai jembatan *Real-Time*. Menggunakan metode Push untuk menerima data dari Edge Node (Sensor), dan Pull yang dipanggil oleh Dashboard Web setiap 2 detik.

Agar tidak menghancurkan performa database MySQL karena diakses ratusan kali per menit, endpoint ini menyimpan state terakhir dalam format flat-file JSON buffer (/storage/buffer.json).

PULL RESPONSE (To Dashboard) 
// GET /api/iot_logging.php?act=pull
{
  "status": "success",
  "rack": { "t": 21.8, "h": 48.2, "s": 150, "c1": 5.12 },
  "room": { "t": 22.4, "h": 50.1, "s": 88,  "c1": 2.40 },
  "doorOnline": true,
  "pir_motion": false,
  "door_status": 1 // 1=Locked, 0=Unlocked
}

save_sensor_logs.php

Snapshot Committer

Berjalan secara otomatis dan senyap di latar belakang via Linux Cron Job (misalnya setiap 10 menit). Skrip ini bertugas membaca state terakhir dari buffer.json, lalu melakukan Commit SQL (INSERT) ke tabel sensor_logs untuk dirangkai menjadi riwayat deret waktu (*Time-Series*).

# Crontab configuration (Run every 10 minutes)

Server Configuration

Konfigurasi Akses
(.htaccess)

Proteksi level direktori (Apache Web Server) sangat penting. Direktori /api/ menyimpan fungsi vital dan file data mentah (seperti buffer.json). Firewall Config ini menjamin keamanan *endpoints*.

Blokir Directory Listing

Menonaktifkan indeks auto-listing sehingga penyerang tidak mendapat pesan selain "403 Forbidden" dan tidak dapat melihat daftar seluruh file kode API.

Isolasi Ekstensi (JSON/ENV)

Memastikan file data mentah (buffer.json) tidak bisa diakses/diunduh publik lewat URL browser, dan hanya bisa dibaca/tulis oleh skrip PHP internal lokal.

/api/.htaccess
# 1. Mencegah Indexing Direktori (Directory Listing) Options -Indexes # 2. Blokir akses langsung pengunjung web ke file JSON <FilesMatch "\.(json)$"> Require all denied </FilesMatch> # 3. Mencegah akses ke konfigurasi sistem kredensial <FilesMatch "^(config\.php|\.env)$"> Require all denied </FilesMatch>
